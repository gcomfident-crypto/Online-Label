# Skill 01：页面设计风格与组件沉淀

## 目标
把 LabelHub 已经稳定形成的页面结构、组件样式和交互规则沉淀为项目内约束，避免后续页面出现视觉碎片化、控件语义不一致和临时样式堆叠。

## 适用范围
仅适用于本项目 `apps/web` 下的前端页面、组件和样式文件。

## 执行原则
- 先复用现有页面范式，再新增样式。
- 用户要求“严格参考”时，必须找到对应参考页面或组件，复用其结构、className、间距、状态和交互方式。
- 不新增与现有 ToB 风格冲突的配色、卡片、阴影、圆角或布局体系。
- 同类信息使用同类组件：状态用状态标签，时间用统一时间单元格，ID 用统一编号样式，操作按钮用统一图标按钮样式。
- 不把说明性文案塞进页面补偿设计问题；页面应通过结构和状态表达清楚。

## 已沉淀标准
- 页面骨架优先采用：标题区、摘要/筛选区、主表格区、分页/操作区。
- 表格类页面优先复用任务管理页结构：
  - `task-management-table-card`
  - `task-table`
  - `task-table-scroll`
  - `task-table__row`
  - `task-table__id`
  - `task-table__cell-inner`
  - `task-table-pagination`
- 时间字段应复用任务管理页同款时间样式：
  - 使用共享组件 `apps/web/src/components/TableDateTimeCell.tsx`
  - DOM 结构为 `.task-date-cell`、`.task-date-cell__date`、`.task-date-cell__time`
  - 日期和时间拆成两行，不直接渲染成一段 `YYYY-MM-DD HH:mm`
- 表格排序按钮不得挤动字段名：
  - 字段名应有稳定布局空间；
  - sort icon 的出现/激活不应改变表头文字位置。
- 选中态必须可见：
  - 当前筛选按钮、状态按钮、选中表格行要有明确边框/底色/高亮；
  - 不能只依赖数据变化让用户推断当前选中项。
- 胶囊、Badge、状态标签要保持克制：
  - 背景浅；
  - 边框轻；
  - 字重中等；
  - 不使用明显阴影。

## 修改页面时的检查清单
- 是否有同类页面可复用。
- 是否新增了全局样式污染。
- 是否改变了已有业务交互。
- 是否同步检查了表头、单元格顺序、空状态 `colSpan`、分页、搜索、行点击。
- 是否新增或更新了覆盖关键 UI 结构的测试。

## 评审口径
这套 skill 说明 LabelHub 的前端不是逐页拼样式，而是在任务管理、模板配置、任务广场、导出中心、质检流转、人工审核等页面中提炼出统一的 ToB 页面范式。后续扩展页面时，开发重点放在业务表达，视觉和交互一致性由沉淀组件保证。
