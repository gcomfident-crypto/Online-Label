# Skill 01：页面设计风格与组件沉淀

## 目标
把当前项目已经稳定运行的页面视觉和交互经验固定成可复用规范，避免后续页面出现视觉碎片化和交互语义不一致。  

## 适用范围
仅适用于 `LabelHub` 项目内的所有前端页面（`apps/web` 下的 UI 模块）。

## 我们沉淀下来的规则
- 统一结构骨架：  
  - 页面区块按“标题区 → 状态与摘要区 → 主内容区 → 操作区”组织。
  - 关键操作区采用左右对齐（如左侧主操作，右侧辅助信息），必要时支持换行避免拥挤。
- 统一信息展示语义：
  - 状态、摘要、版本、时间、操作建议使用一致语义块，不同页面重复实现相同文案形态。
  - 采用最小化文案，避免在标题区堆砌多余元数据。
- 统一交互规范：
  - 选择/排序/过滤按钮要有明确可见状态（hover/active/selected）。
  - 变更动作反馈必须可感知（加载、禁用、完成、错误）。
- 组件样式复用：
  - 优先沿用项目内现有 className、CSS module、现有 UI token 与组件，避免临时自定义样式。
  - 新增 badge、pill、状态块、卡片、时间线条目必须可直接复用，不新增全局污染式样式。

## 交付物
1. `apps/web/src` 里的基础样式、类名和复用组件约定，形成“同类页面一处改动全局生效”的基础。  
2. 各页面只负责内容替换，不单独定义重复视觉系统。  
3. 视觉和交互一致性通过既有测试、人工截图验收、关键 DOM 断言共同保障。

## 评审口径（你要讲给评审的内容）
- 该 skill 说明我们不是做“页面堆叠”，而是在“统一设计系统上扩展业务功能”。
- 新页面上线速度受益于既有模式的可复用，而不是每次重新定义样式。
- 维护成本下降：风格调整一次，多个页面同步受益。

## 成果指标
- 关键页面同类模块的结构一致性达到可复用标准（标题、状态条、时间线、操作区模式一致）。
- 可见交互冲突减少：同类状态不再出现多种表达方式。
- 业务开发以内容和交互为主，不被样式拼接成本拖慢。
